# 境界の召喚士

神話・幻想・機械の英雄を呼び出して戦う、1対1・共通山札のカードゲーム（趣味の試作）。

- 遊ぶ：`index.html`（スマホは「ホーム画面に追加」でアプリのように使えます）
- カードを作る：`editor.html`（カード工房・オーナー用）

## ファイル構成

| --- | --- |

| `js/deck.js` | デッキ編成（絵で一覧・絞り込み・検索・デッキコード） |
| `js/account.js` | アカウント（引き継ぎコード）。所持カード・G・デッキを `seasons/<シーズン>/accounts/<コード>` に保存 |

## カードを更新する流れ

1. `editor.html`（カード工房）で編集する（このブラウザに自動保存される）
2. 「この内容で試遊」で確認する
3. 「公開する」を押す → GitHub の `game-data.json` が直接書き換わり、1〜2分でサイトに反映される

- 初回だけ「その他 → 公開設定」で GitHub の Fine-grained アクセストークン（kyokai リポジトリの Contents: Read and write）を登録する。トークンはそのブラウザにだけ保存される
- 「その他 → 公開履歴」から、以前に公開した内容を読み込んで戻せる
- トークンを使わない場合は「その他 → ファイルに書き出す」で `game-data.json` を作り、GitHub に手動でアップロードする

## 対人戦のしくみ

- 部屋を作った人（ホスト）の端末が対戦処理をすべて行い、盤面を Firebase に書き込む
- 参加した人（ゲスト）は操作を Firebase 経由でホストに送り、盤面を受け取って表示する
- 盤面データは2人とも読めるので、詳しい人なら相手の手札を見ることはできる（友達同士で遊ぶ前提）
- ホストの接続が切れている間、対戦は止まる。ページを開き直すと「前回の対戦に戻る」から再開できる

## デッキ構築ルール（v0.6〜）

- 各自が組んだデッキ（`DECK_SIZE` 枚、同名 `COPY_MAX` 枚まで。カードごとの `limit` がそれより少なければそちら）で戦う
- 開始時：じゃんけん → 勝った人が先攻・後攻を選ぶ → お互い `START_HAND` 枚引き、1回だけ全部引き直せる（マリガン）
- 先攻は最初のターンにカードを引かない
- `game-data.json` の `decks` はサンプルデッキ（CPUもここから選ぶ）

## 所持カードとパック（ベータ版0.8〜）

- 初回起動で16文字の引き継ぎコードを発行し、スターターデッキ一式と `STARTING_GOLD` を配る
- CPU戦の勝利で `REWARD_EASY/NORMAL/HARD`、対人戦の勝利で `REWARD_ONLINE` のGを獲得（負けは0G）
- パックは `game-data.json` の `packs`。最後の1枚は `odds.last`（レア以上）で抽選。被りは所持数に加算
- `config.SEASON` を変えると全員が新規スタート（前のシーズンのデータはFirebaseに残る）
- カード工房での試遊（`?draft`）は、アカウントを使わず全カードを使える

## ベータ用の設定・その他（0.9〜）

- `config.SAMPLE_DECKS`：オンの間は、所持に関係なく全カードで組める「サンプルデッキ」を作れる（カード工房の「報酬・CPU・シーズン」で切り替え）
- 公開時、カード工房で取り込んだイラストは `art/<カードID>-<ハッシュ>.webp` として別ファイルでアップロードされる
- レア度ごとにカードの枠が変わる（コモン：世界色／レア：銀／SR：金／UR：虹色／レジェンド：金の二重枠と光）

## ご意見フォーム（0.9.1〜）

- タイトル画面の「ご意見・感想を送る」から、種類（改善案／不具合・修正／良かった所／いまいちな所／その他）と本文（1000字まで）、名前（任意）を送れる
- 送り先は Firebase の `feedback/<シーズン>/<自動ID>`。書き込みだけ許可していて、アプリからは誰も読めない
- 読むとき：Firebase コンソール → Realtime Database → データ → `feedback`
- 本文と一緒に、カードデータの版・アカウントの引き継ぎコード・端末情報（User-Agent）が保存される
- サンプルデッキでは、カードごとの `limit` に関係なく全カードを `COPY_MAX` 枚まで入れられる（`limit` が0のカードは使えない）

## 起動画面・ホーム・演出（0.9.2〜）

- 起動すると `js/splash.js` の起動画面（タップしてスタート）。3つの世界の帯に、その世界でいちばんレア度の高い「イラスト付き」カードの絵が出る（イラストがなければ文字）。カード工房の試遊では出さない
- ホーム画面：対戦（CPU／友達）・デッキ編成・パック・カード一覧・ご意見。ルール・アカウント・音は右上の歯車（オプション）の中
- `js/motion.js`：攻撃で相手に飛び込む・相手が使ったカードを中央に表示・召喚・撃破・直接攻撃で画面が揺れる・ターンの帯。端末の「視差効果を減らす」がオンなら動きを控えめにする

## デッキ上限・シリアルコード・パック開封・カード枠（0.9.3〜）

- `config.DECK_MAX`：作れるデッキの数（通常・サンプルそれぞれ）。カード工房の「報酬・CPU・シーズン」で変更
- シリアルコード：カード工房の「報酬・CPU・シーズン → シリアルコード」で作る（G・カード・有効期限）。ゲームでは「オプション → シリアルコード」で入力。1アカウント1回
  - `game-data.json` の `serials` にはコードの SHA-256（`kyokai-serial:` ＋コード）だけを置く。コードそのものは作ったブラウザの localStorage（`kyokai-serial-codes`）にだけ控える
  - 受け取り済みはアカウントの `redeemed`（ハッシュ → 日時）に記録
- パック開封（`js/pack.js`）：パックを破る → レア度の低い順に1枚ずつめくる（SR以上は裏のまま光る）→ 一覧。スキップ可
- カード枠（`css/base.css`）：キャラは全面イラスト・丸いコスト・剣形の攻撃・盾形の体力。魔法はアーチ窓・ひし形のコスト・巻物の帯。枠はコモン（世界の色をくすませた色）／レア銀／SR金／UR太い金と光の筋／レジェンド虹色

## ルール変更（v30・2026-10-31）

- 相手プレイヤーは、相手の場に守護がいなければいつでも攻撃できる（以前は「相手の場にキャラがいる間は不可」）
- 直撃：守護を無視して、好きな相手キャラや相手プレイヤーを攻撃できる
- 初期手札5枚・手札上限10枚。`SECOND_BONUS`（後攻が最初に多く引く枚数、初期値0）を追加
- 図鑑・デッキ編成では、持っていないカードのイラストを隠す（サンプルデッキ・試遊では隠さない）
- 後攻ボーナス：後攻の人は「境界の欠片」（コスト0の魔法・このターンだけエナジー+1、使い切り）を1枚持って始まる。`config.SECOND_COIN`（枚数）。マリガンや再起動プロトコルでは山札に戻らない。パック・デッキ・図鑑には出ない（`DEF.coin` だけに存在）
- CPU は、エナジーを増やすだけのカードを「そのあとに打てる手」まで読んで使う（中級でも）

## 検証タブ（カード工房）

- `js/lab.js`（カード工房側）が `index.html?draft&sim` を見えない iframe で開き、`js/simlab.js`（ゲーム側）とpostMessageでやりとりする。編集中の下書きのカードで計算される
- 対戦シミュレーション：選んだデッキを総当たり（席を入れ替えて指定試合数）。デッキ勝率・先攻の勝率・平均ターン・組み合わせ表・カードごとの「使った試合の勝率」
- パックの検証：指定数のパックを開けて、レア度ごとの実際の割合を設定と比較。レジェンドが平均何パックに1回出たか、カードごとの出た回数

## CPU戦の連勝ボーナス（2026-11-01〜）

- CPU戦で同じ強さに連勝すると、2連勝目から報酬が `STREAK_STEP`%（初期値10）ずつ増える。上限は `STREAK_MAX`%（初期値50）。例：中級200G → 200・220・240・260・280・300・300…
- 負け・引き分け・途中でやめる（タイトルに戻る・アプリを閉じる）と、その強さの連勝は0に戻る。強さごとに別々に数える
- 連勝数はアカウントの `streak`（easy / normal / hard）に保存。試合中は `streakLive` に強さを書き、決着で消す。起動時や次の試合の開始時に残っていたら「途中でやめた」とみなして0にする
- 対人戦には付かない。カード工房の試遊でも数えない
- 数値はカード工房の「報酬・CPU・シーズン」で変えられる

## ショップ（魔石）（2026-11-01〜）

- ホームの「ショップ」から使う。通貨はGと別の「魔石」。Gでカードを直接は買えない（パックを開ける意味を残すため）
- 分解：ショップの「分解する」から専用の画面へ。同じカードを `COPY_MAX`（3）枚より多く持っている分を、カードごとに枚数を選んで分解するか、まとめて分解する。もらえる魔石は `STONE_GET_*`（コモン5・レア20・SR50・UR150・レジェンド400）
- 交換：今買えるパックに入っているカードを、魔石で1枚ずつ手に入れる。必要な魔石は `STONE_COST_*`（40・100・400・1000・3000）。3枚持っているカードは交換できない
- パック券：ショップの「パック券と交換」で `STONE_TICKET`（150）魔石につき1枚。パックの画面の「パック券で開ける」で、Gを使わずに1パック開けられる
- 未所持カードは、交換の一覧では手札の「使えないカード」と同じ色あせで見せる（絵は隠さない。買う前に見られるように）
- 魔石・パック券はアカウントの `stones` / `tickets` に保存。Firebase のルールの変更は不要
- レートはすべてカード工房の「報酬・CPU・シーズン」で変えられる
- レートの根拠（シミュレーション）：新しいアカウントからパックを開け続けて、ダブりを分解しながら特定のレジェンドを交換すると、1枚目まで約80パック（中級で約40勝）、3枚そろうまで約160パック（約80勝）。ショップなしなら1枚目まで約240パック以上

## サンプルデッキの報酬（2026-11-01〜）

- サンプルデッキ（所持に関係なく全カードで組めるデッキ）で戦った試合は、勝ってもGをもらえない。CPU戦の連勝にも数えない（伸びも途切れもしない）。対人戦も同じ
- 全カードの調整具合を友達に試してもらうために、ベータ中は機能を残す。正式リリース（全員のGとカードをリセットして一斉に始め直すこと）でサンプルデッキはなくす予定

## 対戦画面の配置（2026-11-01〜）

- 上から：相手の欄 → 相手の場 → 中央（山札・ログ・ターン終了のメダル）→ 自分の場 → 手札 → 自分の欄
- プレイヤーの顔は上下とも中央。場のキャラから矢印を引っ張って、相手の顔に重ねると直接攻撃（タップで選んでからでもよい）
- 手札を場のすぐ下に置いたのは、カードを出すときに自分の欄をまたがないため
- 顔の絵は `playerIcon()`：`p.icon` があればそれ、なければデッキでいちばんレアな絵付きキャラ
- 背景は仮のCSS（`#app.battle::before`）。Gemini の背景画像ができたら差し替える
- 装飾（顔の輪・ひし形の紋章・体力の盾・メダル・空き枠の金具）はすべてCSS。画像AIには枠を描かせない方針のまま

## プレイヤーアイコン（2026-11-01〜）

- 対戦の顔に使う絵。持っているキャラカード（絵があるもの）から選ぶ。カードを集めるほど選べる絵が増える。能力はなく見た目だけ
- 選ぶ場所：ホーム左上の丸いアイコン、または歯車（オプション）→ アイコン
- 「おまかせ」（初期状態）は、使うデッキでいちばんレアな絵付きキャラ。CPUもこの決め方
- 保存はアカウントの `icon`。手放したカードのアイコンは自動で「おまかせ」に戻る
- 対人戦：参加者はデッキと一緒にアイコンを送り、部屋を作った人が盤面（S.players[].icon）に載せる。Firebase のルールの変更は不要
- 丸く切り抜く位置は基本「上から18%」。顔が下の方にある絵だけ `ICON_POS`（js/shared.js）で個別に指定（今は x-rush と garm）

## ホーム画面の配置（2026-11-02〜）

- タイトルは起動画面にあるので、ホームには出さない（オーナー判断）
- 上の段：左に所持Gと魔石、中央に自分のアイコン（タップで選び直し）とデッキ名（タップでデッキ編成）、右にご意見（手紙マーク）と歯車
- 真ん中は背景の絵を見せる空き。下寄りに「CPUと対戦」「友達と対戦」を横並び
- 一番下にメニュー（デッキ・パック・ショップ・カード）を固定。パック券の枚数、分解できるダブりの枚数を赤い印で出す

## 起動画面とホームの飾り棚（2026-11-02〜）

- 起動画面（js/splash.js）：3つの世界の光（左上の金・左下の緑・右の青）の中を、絵のあるすべてのカードから毎回ばらばらに選んだ14枚が、奥・中・手前の3段で回転しながら降る。降りきるたびに、画面に出ていないカードに入れ替わる
- ホームの飾り棚（js/showcase.js）：持っているカードだけを、毎回ばらばらに8枚、輪にして回す。輪の一番奥を通るたびに、まだ出ていない持ちカードへ入れ替わる。指で左右になぞると回せ、タップで詳しく見られる
- どちらも、端末の「視差効果を減らす」がオンなら動きを止める

## タイトルロゴ（2026-11-02〜）

- 飾りは Gemini で描いたもの（`ui/logo-frame.webp`）。真っ黒の背景で描いてもらい、外側の黒だけを抜いた（中の紺の板は残す）
- 文字は画像に入れず、フォント（しっぽり明朝）で重ねる。画像AIは漢字を崩すため（オーナー決定）
- 配置：紋章から降りる光の裂け目を「境」と「界」の間に通す。「の」は「界」の右に小さく、「召喚士」は2行目に大きく
- 板の位置は飾りの高さの42〜86%・幅の22〜78%。別の飾りに差し替えたら、css の `.sp-logo` の位置を測り直す

## カードの裏面（2026-11-02〜）

- Gemini で描いたもの（`ui/card-back.webp`、500×700）。金の枠の線に合わせて 5:7 に切り出した。中央の紋章はタイトルロゴの飾りと同じ形
- 使う場所：パック開封のめくる前（`.os-back`）・対戦の山札（`.pback`）・起動画面で回るカードの裏（`.sp-backface`）

## Gemini の絵（2026-11-02〜）

- 置き場所は `ui/`。元画像はダウンロードした高解像度のもの（縦2576px）を、背景は幅1080pxに縮めて WebP にした
- `bg-battle.webp`：対戦の舞台（`#app.battle::before`）。高さに合わせて敷く。対戦前（じゃんけんなど）は `.pre` で暗く重ねる
- `bg-splash.webp`：起動画面（`.sp-sky`）。3色の光は上に薄く重ねて揺らすだけ
- `bg-home.webp`：ホームの広間（`.homebg`）。元の絵は帯（高さの22〜71%）にしかないので、帯の上下を暗い色へなだらかにつないだ
- `pack-art.webp`：第1弾パックの表（`.bp-body` と一覧の `.packart`）。パックに `art` があればそちらを使う（js/pack.js の `Packs.art()`）
- `rps-g/c/p.webp`：じゃんけんの手。真っ黒の背景から抜いて3つに切り分けた
- 依頼文は docs/bg-list.html
